# wcx2 实验代码（新）说明

> 交付整理后，本目录**只保留报表生成器**；其余一次性探索脚本（M1/M2、P0–P6、时效、容量核查等）已按"仅交付有意义文件"原则移除，其结论与关键数字已固化到仓库根文档（`分析报告（新）.md`、`实验与历史记录（新）.md`）。

## 保留文件

| 脚本 | 用途 |
|---|---|
| `生成RJ模板报告（新）.py` | 由 V5 报告产物重跑 `节点推荐与分布（新）.html` + `_data（新）.js`（RJ v4 四页模板）。用法：`python "生成RJ模板报告（新）.py" [V5输出目录]`，默认取 `recent_month_large_mainstream_v5_sw_7c2.0（新）`；需先按 `采用配置（新）.md` 跑一次 V5 build 生成该目录的报告产物。 |
| `成本归因复算（新）.py` | 复算并校验研发「七牛CDN掉量成本归因」规则（11 项对平校验，全 PASS 才退出码 0）。输入为桌面两张 xlsx，产出结论见 `成本归因与标签诊断（新）.md` 第 1–2 节。 |
| `标签可分性诊断（新）.py` | 对单位建设带宽毛利做方差分解（业务/机房/残差）+ 安慰剂检验，判定平台标签可预测粒度。产出见 `成本归因与标签诊断（新）.md` 第 3 节。 |
| `账本适配（新）.py` | 把现有 V3 pairs（legacy 列名）适配为账本 schema v1，使契约检查可在真实数据上运行（实测 281,461 行 ALL PASS）。 |
| `账本契约检查（新）.py` | 账本 schema v1 校验（键唯一/无空值/带宽>0/白名单/多业务标记），fail-fast；配 `test_ledger_contract.py`（6/6）与 `ledger_schema（新）.md`。 |
| `每日快照（新）.py` | 每日存档不可逆原始状态（bench / 5min 客户视图 / manifest 含 sha256），供 as-of 重建与对账；成本结算件需财务导出。输出 `snapshots/`（已 gitignore）。 |
| `一致性检查（新）.py` | 防错检查：① NaN 陷阱 fixture 自检（防止 `.max()` 静默跳过 NaN）；② V3 审计对账（节点日守恒、剔除类别、clean==outcomes、"一天一个干净业务"、七牛 canonical 归并）；③ 成本归因表分母对账。全 PASS 才退出码 0。 |
| `滚动时间回测（新）.py` | 按采用配置在多时间窗重跑 V5，汇总均值/最差窗（结论见 `滚动回测（新）.md`）。 |
| `门槛看板（新）.py` | 按 RJ §17 九条门槛自动出 PASS/FAIL/待定（结果同步在 `分析报告（新）.md` §9）。 |
| `业务级可信度（新）.py` | 逐业务判定"证据不足"并产出阻止清单；配合 env `V5_BUSINESS_BLOCKLIST` 将命中业务的 Top1 降级为 `暂不推荐执行`（见 `分析报告（新）.md` §10）。 |

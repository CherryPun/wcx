# 数据体量与属性覆盖说明

> 目的：说明本方案训练数据规模、训练侧属性覆盖率及其影响，作为模型可信度与后续改进的依据。

## 1. 训练样本构成

- 样本口径：节点 × 业务 × 满 7 天账（每行一个业务在某节点的 7 天累计成本/收入）。
- 抽样：约 5% 节点（后缀 00–0c），时间窗 2026-03-16 起。
- 时间外切分：按节点引入日（最早业务上线日）前 80% 训练 / 后 20% 测试。
  - 训练节点 4,136，测试节点 1,035。
- 候选业务：训练中支持度达标的业务（主版候选池约 60 个）。

## 2. 什么是“训练侧覆盖”

训练时每一行样本除金额标签外，还需读取该节点的特征（属性）。  
**覆盖 = 在某字段上，非缺失的训练行占比。**

- 覆盖越高，模型越能按节点画像个性化；
- 覆盖低时，缺失行只能落入“缺失”类，模型被迫退回业务级/全局均值。

## 3. 训练侧属性覆盖率（回填后口径）

来源：`05_shared_data/nodes_attr_filled.csv`（对缺失字段已用 node_join / 历史快照回填）。

| 字段 | 非缺失占比（约） | 用途 |
|---|---:|---|
| province / isp | 64% | 区域、运营商画像 |
| corenum | 65% | 计算能力 |
| bw（名义带宽） | 65% | 带宽能力；单位收益口径的分母 |
| deliverytype / device_type | 65% | 交付/设备类型 |
| nattype | 24% | NAT 类型（本身覆盖率即低） |
| 其余容量字段 | 60–65% | 内存/磁盘等 |

> 即训练样本中约有 1/3 的行在关键数值字段上缺失，模型按缺失处理，个性化信号因此受限。

## 4. bw 缺失对单位口径的影响

- 单位收益口径需要“结算 / bw”，bw 必须非缺失。
- 时间外训练中，可用于绝对口径的账行约 8,206；其中 bw>0 可进入单位口径的约 **6,556** 行（测试可用约 276 行）。
- 说明约两成训练行因 bw 缺失无法进入单位带宽口径，单位口径样本量低于绝对口径。

## 5. 缺失成因与现状处理

- 成因：jarvis 属性在“业务上线前一天”那个时点存在未采集/字段未写的情况；部分为源表本身覆盖率低（如 NAT）。
- 现状处理：用 `node_join` 静态字段与历史快照做回填，仍保留缺失标记，缺失行由模型按“缺失”处理，不作插值冒充。

## 6. 补齐方向（列为后续改进项）

- 按“样本日 / 样本日前一日”为训练节点补齐历史画像快照（as-of 对齐），而非只取最新一天；
- 目标：关键字段训练侧覆盖率显著提升（如 ≥90%），同时保证画像快照时间不晚于收益样本日期；
- 补齐后再验证字段是否确实提升模型（金额与命中）——避免为补齐而补齐。
- 这是模型工程通用待办项，与本方案采用的候选/时间外设计相互独立。

## 7. 影响小结

- 覆盖率不足限制了个性化上限，是金额误差（WAPE≈0.82）的成因之一。
- 对绝对口径主版影响是“个性化受限”；对单位带宽口径影响是“可用样本进一步减少”。
- 改进优先级高且可控：先补训练侧画像与 bw，再评估模型增益；不需要扩大节点数。

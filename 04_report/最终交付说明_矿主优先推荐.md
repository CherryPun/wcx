# 最终交付说明：矿主优先 · 相似节点候选 · 诚实参考推荐（v1 主版）

## 1. 定位

给矿主节点推荐业务：候选只来自**相似节点真实跑过的业务**，按**矿主预测 7 天结算**为主序排序，平台利润与容量作软约束。输出 Top1~3 及预测金额，定位为**候选/参考，不承诺“最赚”**。

## 2. 主版结论（时间外验证，新节点=较晚上线、训练未见）

- 测试节点 1035：真实最优业务进 Top1 **35.9%**、进 Top3 **65.4%**
- Top1 平台利润为正比例 **100%**
- 金额（矿主结算）预测 WAPE≈0.82、R²≈0.44（主要短板）

对比：不限制候选（全池打分）时命中≈0，限定到相似节点真实业务后命中 Top1≈36%。方向经诊断验证成立。

## 3. 方法流程

```
输入 node_id
 → 节点画像（nodes_attr_filled.csv）
 → 相似节点召回（画像余弦 Top15）
 → 候选 = 相似节点真实跑过且训练支持>=20 的业务 ∪ 该节点自身满7天账
 → XGB 预测 cost/profit（direct；训练于按引入日时间切分的早期节点）
 → 排序：pred_cost 主序 + 平台利润<=0 软降权 + 容量超限软降权
 → 输出 Top1~3：业务、预测矿主结算、预测平台利润
```

## 4. 与 HRR / yzx / RJ 的差异（“不照搬”点）

| | HRR | yzx | RJ | 本方案 |
|---|---|---|---|---|
| 候选 | 全池反事实打分 | 相似配置分类 | 主流业务池 | **相似节点真实跑过**（有证据才进） |
| 排序目标 | 金额/利润 | 命中常跑 | 矿主+平台 50/50 | **矿主结算主序 + 平台/容量软约束** |
| 冷启动定位 | 外推 | 匹配 | 参考 | **候选/参考，不承诺最赚** |
| 验证 | 遮挡 | 分类命中 | 时间外+区间 | 时间外 + 候选质量（不把“命中被分配业务”当有效性尺子） |

## 5. 关键实验证据（本机已完成）

- 时间外切分后：全池打分命中≈0 → 证明需候选收窄。
- 相似节点候选后：Top1≈36%、Top3≈65%。
- 双塔召回（stage3）在随机切分下有效，但时间外冷启动未证明；主版用相似节点召回替代，更简单可解释。
- 带宽辅助分：仅 17/1035 测试节点有自身账数据，开/关几乎无差别（Top1 只变 1 个）→ 保留但注明仅对存量候选生效。
- 金额误差改进拆解：neighbor 特征无效（WAPE 反升 0.84→0.90）；WAPE 改善主要来自 log1p（0.77），代价 R² 下降（0.31）。主版保持 direct（命中优先）。

## 7. 局限（须随交付说明）

1. 金额预测 WAPE≈0.82，绝对值仅供排序与参考，不承诺结算精度。
2. “命中”尺子是“真实被分配且结算最高”的业务进不进推荐，属候选质量参考，不是反事实收益证明。
3. 冷启动无真实“未跑业务收益”标签，“更赚”为相似节点统计推断。
4. 容量为近 7 天流量近似，非客户真实容量。
5. 样本：5% 节点抽样、满 7 天账、7 天累计口径（与 HRR 资产同源，非 RJ 日单位带宽）。

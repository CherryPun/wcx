## 二、口径与产品上的最优做法（5% 阶段收敛记录；与顶部全库定稿冲突处以顶部为准）

1. **分层面汇报**：主版命中由 ant/smallBox（95.9% 测试）主导；对外区分 smallBox 与 IDC，IDC 样本需扩。
2. **稳健性披露**：命中波动（hit1 0.09~0.36）根因＝“相似邻居真实业务”候选法对训练节点构成敏感（ant 聚类放大），非随机；对外给区间而非单点。
3. **“在跑”列语义**：只表示“有连续账+有收入”，不等于有量；需低量/名义标注（backlog，主版未改）。
4. **复核闭环**：以 `review_list.csv` 为底表，优先“当前实际亏而 Top1 预测正（231 个）”做人工复核，不做自动切换。
5. **数据事实**：真实 `buildBandwidth` 宽表已有（可作准入/容量展示）；客户↔虚拟映射、成本归因口径以权威/平台就绪为准，不提前硬接。

## 三、判断为“不应做”的项

- 以 node 级容量为分母的单位口径（同一节点常数缩放，无区分）；
- per(node,business) 单位口径的单独建模（oracle 相同率 99.9%，分歧点绝对损失远大于单位增益）；
- 以降集中为目标、不度量真实收益的去偏/惩罚（放大惩罚实验已证明只降命中）；
- ant 主体的 as-of 画像补齐（上游无档案/VM 无时序，无源可回填）。

## 四、真正能提升模型的后续

1. IDC/全库扩样：**已完成**——全库非 ant（25,860→画像交集 14,966）扩样并定稿，时间外 n=2,994，家族粒 21.0/51.7（取代“42 个测试节点不可信”的旧状）。
2. **可达量/利用率**：接入更全带宽数据后做“可达量校准层”，把空载预测向真实到手收敛（目标=分层误差与真实收益）。
3. **日粒度标签口径**：连续段权重 + 同日多业务唯一归属，照顾分时/切换节点；大重构，作为专项。
4. 画像/映射/成本口径等在权威数据或平台就绪后按需跟进。

> 用 K=15（冻结）的矿主结算主序基线，对外披露家族粒/ID 粒两行命中与 n；交付以复核表与低量标注为准；可达/日粒度改造列为后续实验（本轮不再以混训 36% 或 big 13.8% 作为基线）。

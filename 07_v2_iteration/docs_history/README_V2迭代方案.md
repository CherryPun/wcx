## 3. 执行顺序与各阶段

### 阶段 A：训练画像 as-of 补齐并复验（D3 + M1'）——先做
- 问题依据：训练侧关键字段覆盖率约 64%（约 1/3 训练行缺失），金额 WAPE≈0.82 / R²≈0.44；画像取“上线前一天”当天快照导致字段不全。
- 做法：对每个训练样本（节点×业务 满7天账）按其账样本日前一日取画像快照（数据源：jarvis.node_join / node_analysis_data，按日分批拉取，参照 5171 分批方式），产出 `attrs_asof.csv`。
- 校验：新旧两版各字段训练侧覆盖率对比（目标 ≥90%），抽查 30 个节点核对填充值确实来自样本日前历史快照。
- 复验：用补全画像重训成本模型，同一时间外切分（8/2）同一测试集，对比 WAPE/R²/命中（Top1/Top3）；无论是否提升都记录结论。
- 验收：输出覆盖率前后表 + 复验指标对比 + 结论（提升 or 无改善）。

### 阶段 B：参数校准（M6 TopK + M5 利润软约束系数）
- M6：相似节点 TopK（10/15/20/30）与候选是否含自身账，做时间外候选质量网格 → Top1/Top3 命中、候选覆盖率、金额 WAPE 敏感性表。
- M5：平台利润软降权 W_PROFIT 与“降权 vs 过滤 vs 仅标注”，对比 Top1 利润为正率（当前 100%）/命中/平均利润 → 系数结论。
- 验收：两张敏感性表 + 默认参数是否调整的建议。

### 阶段 C：多窗口滚动回测（V1）
- 做法：节点按引入日切多窗口（如逐月滚动），每窗口重跑主版，记录命中/Top3/WAPE/R²/利润为正率。
- 验收：多窗口指标表 + 稳定性结论；确认阶段 A/B 的结论不是单点切分侥幸。

### 阶段 D：可达量特征离线初探（M2'，只算不改调度）
- 问题依据：空载/低量节点预测明显虚高（例 209 vs 3,236、15 vs 2,230）。
- 做法：① 用 node_analysis_data（5 分钟/时点）或宽表 peak95 建每节点历史利用率特征集（日95分布、近7/30天均值、有账占比、空转时长）→ `reachable_feats.csv`；② 拼入金额模型重训，分层看空载/正常节点 WAPE 变化，确认能否缓解虚高且不伤命中。
- 边界：只建模与离线评估；不推动调度、不上线。
- 验收：特征统计表 + 空载层误差前后对比 + 是否值得转正式层的结论。

### 阶段 E：人工复核底表产出（V3'）
- 做法：基于阶段 A 新基线输出可下钻复核清单：节点 = 当前在跑(近7天实际) + Top1~3(预测) + 预测 vs 现状差异 + 可达/容量提示；落 CSV/HTML。
- 性质：交付决策参考表；采纳/执行留业务侧。
- 验收：生成复核清单文件，抽查 10 行口径正确。

## 4. 预期收益评估（相对 v1 主版，供验收对照）

> 基调：V2 的真实价值是“更诚实、分层误差收敛、结论更稳”，不是把 hit@1/WAPE 大幅刷高。
> 量级为预期方向，不承诺；以跑出的实验为准，且对比须同窗口、同测试集（用阶段 C 滚动回测）。
> 若 D1（成本归因调整）在 V2 完成前回流标签口径，新旧指标不可直接比，需先重建基线。

| V2 阶段/项 | v1 现状 | 预期变化方向 | 量级与信心 |
|---|---|---|---|
| A 画像 as-of 补齐复验 | 关键字段覆盖约 64%、WAPE≈0.82 | 金额误差小幅改善；省级/运营商个性化更好 | 整体 WAPE 可能小幅下降（不承诺具体值）；别期待骤降 |
| D 可达量/利用率校准层 | 空载/低量节点预测虚高（例 209 vs 3,236） | 空载层“虚高收敛”，预测向实际到手靠拢 | 对分层误差收益明显；整体 WAPE 贡献有限；对空载节点是主动下调预测，不是刷分 |
| B TopK / 利润软约束系数校准 | TopK=15、W_PROFIT=0.8 未校准 | 命中/利润为正率微调 | hit±1~3pp 量级；Top1 利润为正率仍接近 100% |
| C 滚动回测 | 单次 8/2 切分 | 确认 35.9/65.4 稳定而非单点侥幸 | 稳健性证明，不改分数 |
| E 人工复核底表 | 有 HTML，缺分层/差异汇总 | 交付可信度提升，减少“现状 vs 预测”误读 | 产品价值，不改模型数字 |

**大概率不会提升**
- hit@1/@3（35.9%/65.4%）：由候选与标签口径决定，V2 不动候选/标签，基本维持或 ±1~3pp；
- WAPE 不会断崖下降：标签本身是实际给量产物，未引入真实给量与容量前金额上限受标签约束；
- 利润软约束类接近上限，提升空间小。

**反向效果提醒**：D 阶段会让空载/低量节点预测金额下降（更接近到手）。评估请用“空载层误差/极端偏差”等分层指标，而非只看均值或“预测高不高”。

**与挂起项的关系**：D1（成本归因调整）回流后标签会变，先用阶段 C 重建基线再评估提升，避免新旧不可比。

| `mainstream_business_allowlist.csv` | 2026-08 | 不能直接用 | 可自造：按主流客户（字节/百度/优酷/快手/腾讯/爱奇艺/B站/七牛主档）+ 签约审计整理，以其为核对基线 |
| `buildBandwidth`（真实建设带宽口径） | 无时点（字段） | 能复用字段 | 能自造且应优先做：`test.node_day_ops_wide_full.buildBandwidth`(Mbps) 按自己窗口拉取，替换名义 `bw`（对应 M3） |
| 方法与设计（V3 同业务连续权重、V5 倾向权重修正、DR 诊断、可信度区间、单位收益=金额/buildBandwidth） | 公开方法 | 能直接借鉴思路 | 可在本代按自己训练集实现；倾向权重建议列入 V2 后续实验 |

结论：
- **能直接用的**：代码/方法/字段口径（绑定抓取脚本、buildBandwidth 字段、倾向权重与可信度做法）。
- **不能直接用、但能自己造**：全部训练产物（重训）、绑定审计映射（降级自造）、主流 allowlist（自审）、buildBandwidth（宽表自取）。
- **自己造不了/只能要**：权威版 NiuLink 虚拟绑定（需 `NIULINK_AUTH` 鉴权）；如无该权限，先向 RJ 或平台索取最新一份，或先用自造审计映射并标注“待权威复核”。
